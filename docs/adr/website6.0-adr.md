## ADR-002 移动端升级为一等验收项
- 日期：2026-10-23
- 状态：已采纳
- 背景：原方案中移动端仅是 Lighthouse 移动端指标（Perf≥90/A11y≥95）与 375px 无遮挡的兼容底线；站主新增硬性要求"站点需要支持移动端"。
- 决策：移动体验升为一等验收项，不再只是兼容底线。落地要求：移动优先断点（375px 基线）、触控目标 ≥44px、拇指区布局、折叠导航进入设计与验收 spec（设计逐页 spec、产品移动端专项验收清单、M4 验证）。
- 后果：设计与产品的既有交付物需增补移动端章节；测试验收清单需并入移动专项条款。

## ADR-003 LLM key 晚点提供，管线降级模式先行
- 日期：2026-10-23
- 状态：已采纳（Q8 挂起，不阻塞）
- 背景：Q8 原建议站主提供 1 个自持 key（推荐 Gemini 免费档）；站主表示 key 晚点提供。
- 决策：M1/M2 照常开工；key 到位前，构建期 AI 新闻管线（落点①）按降级模式=纯 RSS 聚合（无 AI 摘要）验证；到位后一步注入 Actions Secrets 即启用摘要+打标签。后端准备的密钥无关件（源白名单、prompt 模板、news.json schema、提供商适配层）先行就绪。
- 后果：验收需分别覆盖降级模式与完整模式两个状态；提供商解耦设计保证换 key 只改 Secrets+适配层。

## ADR-004 域名换绑暂缓，保持人工门禁
- 日期：2026-10-23
- 状态：已采纳
- 背景：jary8.com DNS 实测已就位（CNAME → longzhengyun.github.io），接管不需改解析；但 GitHub 自定义域名仓库级唯一，须先解绑 website5.0 再绑 website6.0。
- 决策：website6.0 先在 `longzhengyun.github.io/website6.0` 路径部署验收（M4）；域名换绑（M5）为独立人工门禁，时机由站主自定，团队不代为操作。换绑全程可逆（回滚=反向执行两步），website5.0 换绑后保留路径访问。
- 后果：站主操作清单中域名两步明确标注"暂缓，时机由站主定"；上线复验（M6）在换绑后才执行。
