## R15 首页极简单屏（站主原话："首页不要加新闻，或者加小块新闻，弱化，保证首页只有一屏，极简"）

### 变体裁定（项目 seq=280 终裁，取代原"选一"规则）
- **定稿形态：设计混合变体**——桌面 = 超紧凑新闻动态条（≤64px、单行两项、仅标题级，满足并严于原 B 的 5 项硬约束，滚动 0% 口径优于 ≤10% 容差）；移动端 = 新闻整块 DOM 移除。
- **降级预案（纯 A）**：前端实施后若 1280×720 实测破屏（scrollHeight>视口高），不返工，直接删动态条回落纯 A（首页 HTML 无任何新闻条目节点），一步回退。
- 产品备注：原建议首选纯 A 作为终态不再坚持；混合变体保留新闻橱窗的产品价值成立，前提是 AC-R15-02 判定随形态切换。

### 验收条款
- **AC-R15-01 单屏硬口径**：1280×720（桌面）与 375×667（移动）两视口下，首页 `document.scrollHeight ≤ viewport 高 × 1.10`（即无纵向滚动或滚动 ≤10%；项目建议口径采纳）。页脚允许落在 ≤10% 的滚动余量内。**简历暗线口径（项目裁定①，取代原"页脚 Resume 不得移出 DOM/不可达"表述）：按页面级可达验收——/resume 页面存在且可经 About 内链 + ⌘K 到达即合规；移动页脚单行压缩、Resume 不再作为页脚硬要求。header/tab bar 主导航禁"简历"字样条款（AC-P05）不变。**
- **AC-R15-02 新闻弱化判定（随定稿混合变体执行）**：桌面：动态条总高 ≤64px、单行 ≤2 条、仅标题级、不抢站点名/身份句视觉权重、无纵向滚动贡献（0% 口径）；移动：首页 HTML 无新闻条目节点。回落纯 A 时：两视口均无新闻条目节点。
- **AC-R15-03 News 可达性不回退**：无论 A/B，主导航/底部 tab 条/⌘K 三路径到 /news 均保持一级可达（交叉 AC-H2、AC-P05 既有断言不得因首页改造回归）。
- **AC-R15-04 极简元素守恒**：首页仍只含 站点名（佳瑞网/jary8）+ 身份/副标题 + 单一视觉焦点（可变字体呼吸）+（R16 动态副标题）+ 导航/页脚骨架；不新增营销模块、图片轮播、统计卡片。
- **AC-R15-05 移动端联动回归**：改造后 375/390/430 三视口 scrollWidth==clientWidth（防 BUG-M4-01 类横向溢出回归）；200% 文字缩放下仍无横向溢出（M-A5 联动）；单屏口径允许纵向 ≤10% 滚动但禁止通过 `overflow:hidden` 裁切内容作弊（页脚元素必须可滚动到达）。
- **AC-R15-06 呼吸动画在单屏约束**：焦点动画不得引发 CLS>0 或可见位移；prefers-reduced-motion 降级仍满足单屏口径。

## R16 副标题动态化（站主原话："副标题文案做成动态变化的，即每次刷新内容不同"）

### 口径定义
"每次刷新内容不同" = 页面加载时客户端从内嵌文案池随机取一条展示（SSG 正确姿势=构建打包池+加载时随机，前端分派已确认）；**不要求**同会话内定时轮播，且**不建议**实现无用户操作的定时切换（动效敏感/读屏干扰，站主原话仅"刷新"）。

### 验收条款
- **AC-R16-01 池在页内、零外部请求**：文案池（设计出 ≥10 条）内联/打包进首页资源；冷加载 Network 断言维持"白名单外零外部请求"（AC-AI-D02 口径不因 R16 回归）。
- **AC-R16-02 刷新即变**：同一地址连续 reload ≥8 次，副标题文本出现 ≥3 种不同值（概率性口径，confidence=high 因 10 条池下该结果近乎必然）；可辅以源码/构建产物断言：池长度 ≥10 且选择逻辑为每次加载随机（非构建期固定）。
- **AC-R16-03 CLS≈0**：副标题槽位在首屏布局前预留（文本在固定行盒内原位替换，或替换发生在首次 paint 前）；DevTools reload 会话 CLS 中来自副标题节点的贡献 = 0（整体 CLS 仍守 <0.05 门禁）；替换不引起站点名/焦点元素位移。
- **AC-R16-04 无 AI 宣称**：池文案与页面任何文字不得宣称副标题"由 AI 生成/实时生成"；实现为静态池随机即如实表述（延续 AC-AI-D03 无虚假 AI 宣称口径）。
- **AC-R16-05 降级与可达**：禁 JS 访客看到池首条稳定副标题（SSR 默认值，按设计 spec 三行制：站点名/固定身份行不轮播/动态池行取一），内容仍成立；副标题节点在 DOM 流内、可被读屏正常朗读，无 aria-live 播报抖动；**池文案长度按设计定稿口径 ≤20 全角字（比产品原建议 ≤24 更严，取代执行）**，最长条目在 375px 与 200% 缩放下不破版。
- **AC-R16-06 首屏 JS 预算**：动态副标题新增 JS ≤2KB（gzip），不引入框架级运行时（首屏 JS≤150KB CI 红线联动）。

## R17 新闻只要中文（站主原话："新闻只要中文的"）

### 双模式裁定（产品结论）
1. **ai 模式（key 网络问题走通后）**：全量译文达标——feed 内条目一律中文标题+中文简介展示。达标口径：news.json 每条 `title_zh` 与 `summary_zh` 均含 CJK 字符（正则 `/[\u4e00-\u9fff]/`），页面展示优先 title_zh；句内英文专有名词（Chrome、WebGPU 等）允许。**译文校验失败的条目不入 feed**（后端 postValidate 追加"无中文即拒绝"规则；沿用现有失败回落上一版机制）。
2. **降级模式（rss_only，当前线上态）——接受性裁定：同意"仅 zh 源条目入 feed"为合规形态**，但附两个前置条件，否则等于清空新闻页：
   - **条件① 中文源扩容**：现 sources.json 10 源仅 infoq-cn 一个 zh 源且 enabled=false+verify 未过——单源撑不起 feed（48h 窗口空增量常态）。要求后端/实施验证启用 infoq-cn 并新增 ≥2 个中文可靠源（候选方向：阮一峰周刊（周更，配合 fetch_window 放宽）、OSCHINA、掘金首页精选；具体 RSS 可达性以后端 preflight 实测为准，产品不拍板源名）。目标：**zh 活跃源 ≥3**。
   - **条件② 空态可接受**：当轮 zh 条目为 0 时，/news 显示空态文案（如"本期暂无更新，稍后再来"）而非空白/报错；首页小块（若 R15 选 B）同步不渲染或显示同一空态。空态本身不算缺陷，但连续 3 个抓取周期 zh 条目恒 0 视为源覆盖不足，回到条件① 扩容。
3. **英文源处理策略（建议，供项目转后端实施）**：en 源在 sources.json 保留不删（lang 标记已有），rss_only 模式按**源级 lang 字段过滤**（不做逐条文本语言推断，避免误判），ai 模式恢复全源（译文全覆盖后天然满足 R17）。**否决**"降级模式加确定性机器翻译兜底"路线——会引入新的运行时外部请求/密钥面，违背零成本降级与 D02 网络白名单口径。

### 验收条款
- **AC-R17-01 ai 模式全量中文**：ai run 后 news.json items 100% 过 CJK 断言（title_zh+summary_zh）；/news 渲染态扫描无非纯中文标题条目（英文专有名词混排豁免）；postValidate"无中文即拒绝"有代码证据+stats 可观察（拒绝计数或错误记录）。
- **AC-R17-02 降级模式源级过滤**：rss_only run 产物 news.json 中 source 均满足 sources.json lang=zh；stats 记录被过滤的 en 源/条目数（可观测性，供判断扩容压力）；schema 不变（契约零漂移，后端分派口径）。
- **AC-R17-03 zh 源覆盖**：sources.json 中 enabled=true 且 lang=zh 的源 ≥3；infoq-cn verify 状态有实测结论（过则 enabled，不过换备选并回报）。
- **AC-R17-04 空态展示**：mock 空增量（或真实零 zh 轮）下 /news 空态文案在位、非白屏、状态码 200；空态文案无 AI 宣称。
- **AC-R17-05 存量英文条目消化**：切换过滤后线上 news.json 存量 en 源条目不残留（管线重建 feed 或按既有窗口自然滚出——要求实施采用"立即只保留 zh"的一次性清洗，避免验收期混合态歧义；清洗动作等同一次正常管线产物更新）。
- **AC-R17-06 既有数据条款联动**：AC-P04（≥5 条真实）在 zh-only 口径下重测；条目回源比对仍按 URL 200+标题命中口径；若 zh 源供给导致条目 <5，判 AC-R17-03 不达标（源不足），不判新闻页缺陷。

## News 页 Lighthouse 缺口裁定（产品补充，回应项目 seq=308 询问）

事实：devops 正式轮 news perf 0.71 / LCP 3.89s（其余三页 0.99/~1.3s）。
裁定：**本轮列观察项、不立即开修复单（同意项目汇总意见），但设硬性检查点，非开放式搁置**：
1. 前提修正：项目"R17 清洗后 feed 会瘦身"的假设**不成立**——后端 seq=305 本地最新产物为 93 条全中文（多于现存量），回写上线后列表更长，重测数值不会自然好转。检查点必须带预案而非裸重测。
2. 检查点：M4.1（R15/R16）合入 + PAT 回写打通后的复验窗口实测 news 页——**perf ≥0.90 且 LCP ≤2.5s 为过线**；未过线即转修复项，owner 前端，本条并入测试清单随 AC-G05 执行。
3. 修复方向预案（届时无需再裁定口径）：首屏限 N 条 + 分页/懒加载或"加载更多"，约束=不违反 AC-R17-04 空态、AC-P04（feed ≥5 条真实）、AC-R15-05 溢出回归与 D02 网络白名单；纯 CSS/原生 JS 实现（首屏 JS≤2KB 预算联动 AC-R16-06 仅约束副标题，不新增框架运行时）。
