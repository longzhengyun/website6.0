## R15 首页单屏：新闻「小块 vs 移除」取舍

### 结论

**桌面：保留超紧凑"动态条"（非卡片）；移动：整块移除。** 两档都不做纵向滚动，1280×720 与 375×667 下 100% 单屏（滚动 0%，优于产品建议的 ≤10% 口径）。

### 理由

1. 站主原话给了两个许可——"不加，或加小块弱化"。单屏预算下，3 张新闻卡（现状约 3×140px+标题区）必然破屏，卡片形态不可保留。
2. 完全移除会丢掉"站点每天在活"的信号（新闻管线是本站最大技术卖点之一，首页是它的橱窗）；桌面留一条文字动态可以两全。
3. 移动端 667px 高预算太紧（display 呼吸+身份+副标题+tab 条已占大头），任何附加内容都威胁单屏——移除是唯一稳态解；新闻可达性由底部 tab 条「News」项保证，IA 无损。

### 桌面动态条 spec（替换现状 3 卡区块）

```
01/ Chrome 141 发布 CSS scope        · 02/ 千问平台模型更新        →  all news
05-22                                    05-21
```

- 结构：单行两项（非三——720p 下横向 ≤1080 版心一行放三条完整标题会截断过多），每条 = `mono 编号` + 标题（t-small，单行省略号）+ 日期（t-label ink-faint 第二行）；行尾 `全部新闻 →`（arrow-link 规范不变）。
- 整条区域高 ≤64px；点击任一标题=新窗口直跳外链（noopener），点行尾进 /news。
- 位置：贴视口底部（footer 之上合并为同一收束区），hero 区其余留白全部还给呼吸感。
- 样式全部复用现有 token，无新增色/字级；accent 预算不增（选中/交互态同 A4）。

### 首页垂直预算（供前端与测试核对）

| 区域 | 桌面 1280×720 | 移动 375×667 |
|---|---|---|
| 顶栏 | 56px（h-14 现状） | 56px |
| Hero（站名 L1+身份+R16 副标题） | pt 20vh + 内容 ≈ 400px | 居中于 tab 条上方可视区，display 2.25rem/3rem 现状 |
| 新闻动态条 | ≤64px | **0（移除）** |
| 页脚（单行化：简历暗线 · 邮箱 · ©） | ≤48px | 并入 tab 条上方 1 行 44px |

配套调整（前端实施时确认）：桌面 display 从 6.5rem 收到 5.5rem 以内亦可（720p 高度更稳），我无强意见，二选一由前端按构建现状定；移动 hero 垂直居中改用 `100svh` 防 iOS 地址栏跳动。

## R16 动态副标题

### 版式位置

首页身份结构改为三行制（L1 版式增量）：

1. `jary8·佳瑞网`（display，现状）
2. **固定身份行**：`web 前端开发工程师`（t-h2 ink-muted，现状 tagline 位置）——站主硬需求 5"站长身份"必须稳定，不轮播；
3. **轮播副行**：动态文案池，t-label mono、ink-faint、前缀 `▍`（终端光标延续 A 方向人格）。

### 文案池（12 条，≤20 全角字，贴合前端+AI 人设；站主授权自主发挥，上线前可整池换）

1. 今天也在追最新的 Chrome 版本
2. CSS 的新能力，我替你验证过了
3. 新闻由 RSS 喂养，摘要交给 AI
4. 本站零 Cookie、零外部请求
5. 用浏览器原生的，省下的都是世界
6. 一行 JS 不写的滚动动效
7. 每天清晨，新闻自己长出来
8. 运行时零密钥的 AI 站点
9. 可变字体在呼吸，它还活着
10. 把浏览器能做的，做到最新（现 C1 文案，收进池作锚点）
11. ⌘K 是本站最短的路
12. 前端的手艺，藏在无障碍细节里

事实锚点条款：第 4/8 条是可验证事实（D02 Network 断言背书），若未来引入外部请求须同步删改——建议知识侧登记为「文案-事实一致性」维护项。池内不放了分数/KB 数等易过期数字（避免版本号 141 类硬编码，第 1 条不落具体版本号）。

### 切换交互规范（对前端的硬约束）

| 项 | 规范 |
|---|---|
| 选择策略 | 每次页面加载随机取一（`Math.random`）；同会话内站内跳转**不**重抽（仅整页 refresh 变），避免 SPA 感割裂；不做持久化 |
| SSG 正确姿势 | 构建期渲染池第 1 条为静态文本（保无 JS 用户与 LCP），客户端脚本加载后立即替换为随机条目 |
| CLS 零位移 | 副行固定单行、固定行高（t-label 1.4），池文案均在宽度上限内且**不换行溢出**（容器 `overflow:hidden; text-overflow:ellipsis` 兜底）；首帧静态文本→替换同位置同字号，位移=0 |
| 无闪烁 | 替换为瞬时完成，或 ≤120ms opacity 0.96→1 微淡入（不得有可见空帧）；`prefers-reduced-motion: reduce` 时直接替换无过渡 |
| A11y | 轮播文本**不进** aria-live（不自动播报）；`▍` 前缀 aria-hidden；屏幕阅读器读到的即所显示条目（DOM 文本替换，非 CSS content） |
| 红线 | 禁新增外部请求（池打包内联）；禁 AI 生成宣称（文案池为人工内容，符合 D03 无虚假宣称条款） |

## 验收对齐建议（供产品 v1.6 引用）

- R15：1280×720 / 375×667 两档 `document.scrollHeight <= viewport高度`（滚动 0%）；桌面动态条 ≤64px 高、移动 DOM 中新闻区块不存在（非隐藏）；tab 条/主导航 News 可达性不变。
- R16：连续刷新 ≥10 次出现 ≥3 个不同条目；CLS=0（Lighthouse 实测）；无 JS 时显示池首条；200% 缩放下副行仍单行不挤压 R15 预算（前端复验 BUG-M4-03 同法）。

## 待裁定/风险（不阻塞实施）

1. 移动页脚若压缩为单行，「在线简历」暗线只余 About 内链+⌘K——是否可接受？我建议可接受（tab 条高度优先级更高），请产品确认口径。
2. 桌面 display 6.5rem→5.5rem 为可选优化，若前端实测 720p 原 6.5rem 也能单屏则不动（改动最小优先）。
