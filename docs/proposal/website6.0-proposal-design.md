# website6.0 视觉方向提案（设计）

作者：设计｜2026-10-23
阶段：方案（不出码）。依据：shared/website6.0-requirements.md
范围：3 个视觉方向概念 + 推荐结论 + 风险 + 设计侧头脑风暴功能点。

## 0. 设计命题拆解

需求对设计的三重约束，决定了方向必须同时满足：

| 约束 | 设计含义 |
|---|---|
| 首页极简（站点名 + 站长身份） | 视觉冲击只能来自「字、色、动」本身，不靠内容堆砌 |
| 展现最前沿前端技术 + AI | 技术即视觉语言：动效、渲染、交互本身就是装饰，而不是贴上去的特效 |
| 体现站长技术 | 「看得到手艺」：细节完成度（状态、节奏、无障碍、响应式）要能被同行一眼识别 |

内容结构基线（三个方向共用）：
- 首页：站点名 + 一句话身份 + 单一视觉焦点；业内新闻列表（标题 + 简介 + 整卡直跳外链）；简历入口弱化为页脚/次级角落小链接，不进主导航。
- 导航只保留必要项，其余页面按产品 IA 补充。

## 方向 A：「精密终端」Precision Terminal —— 工程美学

**一句话**：把开发者最熟悉的终端/编辑器语言，用高完成度的瑞士式栅格重新演绎。

- **风格**：半拟态终端美学。等宽字体为骨，细线分隔、密集栅格、编号系统（01/02/03 段落索引、ASCII 分隔线），像一份精心排版的 man page，而不是廉价的「黑客风」。
- **排版**：主体正文用现代无衬线（如 Geist Sans / Inter），代码级元素用等宽（Geist Mono / JetBrains Mono）；首页站点名用超大号等宽 + 字距收紧，制造「终端横幅」感。变宽字体做 h1 的字符级动画（逐字浮现）。
- **色彩**：近黑 `#0A0C10` 背景 + 灰阶层级（4 级灰）+ 单一信号色（磷光青 `#5EEAD4` 或琥珀 `#FBBF24` 二选一，由站主裁定）。信号色只用于交互焦点与选中态，克制即高级。提供精确反色亮色模式。
- **动效**：命令面板式导航（⌘K 呼出）；光标跟随的微型终端提示符；新闻条目 hover 时左侧出现 `>` 前缀；输出型渐入（逐行 reveal，非整块 fade）。全部动效可用 CSS + 少量 JS 实现，60fps、可 prefers-reduced-motion 降级。
- **如何体现站长技术**：⌘K 命令面板、字符级排版控制、theme token 系统、reduced-motion 变体——这些是同行一眼能认出的「内功」。
- **推荐理由**：与「web 前端工程师」身份天然契合；极简要求下靠字体与栅格就能立住；实现成本中等、GitHub Pages 完全无压力；AI 结合点自然（终端里嵌一个 AI 问答 prompt 行）。
- **风险**：暗色终端风在开发者个人站中较常见，差异化必须靠排版精度和细节动效撑住，否则沦为模板感；纯暗色对新闻长文阅读舒适度有要求，需做好灰阶对比度（WCAG AA）。

## 方向 B：「瑞士排版 + 动态字体」Editorial Variable —— 设计功底流

**一句话**：一张会呼吸的瑞士海报。大字号可变字体（Variable Font）+ 严格基线栅格 + 极少色彩。

- **风格**：编辑设计/国际主义排版风格（Swiss style）。不对称大留白、超大 h1 与极小 meta 信息的极端字号对比、细分割线、编号体系。整站像一本个人杂志。
- **排版**：核心卖点——1-2 款可变字体（如 Geist VF / Fraunces VF / Inter VF）贯穿全站，字重、字宽、optical size 随滚动进度与 hover 实时插值变化；首页站点名在视口内做慢速 `font-variation-settings` 呼吸动画。这一招直接展示「最前沿 CSS 能力」（font-variation + scroll-driven animations）。
- **色彩**：纸白 `#FAFAF8` 底 + 近黑墨 `#111312` + 单一强调色（建议朱红 `#E5484D` 或克莱因蓝 `#3E53BA`）。亮色为主，暗色模式反相。色彩极少，对比度天然易达标。
- **动效**：scroll-driven animations（CSS `animation-timeline: view()`，2024+ 前沿原生 API，无需 JS 库）做条目入场与字号变化；hover 只做字重/颜色切换，克制；新闻列表像杂志目录（index 风格：编号、标题、一句话摘要、箭头直跳）。
- **如何体现站长技术**：用原生 CSS scroll-driven animations 和可变字体插值做出通常需要 GSAP 才能实现的效果——「不用库」本身就是技术宣言；栅格与基线的完成度体现设计功底。
- **推荐理由**：在开发者个人站中最具差异化（大多数人做暗色终端，没人做编辑部）；与「极简首页」要求完美契合——大字 + 留白即全部；性能最好（纯 CSS 动效，无 WebGL 负担）；A11y 与对比度最易保证。
- **风险**：动态性弱于 A/C，「前沿感」依赖 CSS 新 API 的展示说明，普通访客无感（但站主和目标受众——同行——能看懂）；中文可变字体选择少，主标题建议英文/数字承担动态字体效果，中文用高质量黑体（如思源黑体不同字重切换）；纯排版路线如果字号系统失手会显得空洞。

## 方向 C：「生成式画布」Generative Canvas —— 技术炫技流

**一句话**：首页是一幅由 WebGL/Canvas 实时渲染、可被 AI 改写的生成艺术，网站本身就是作品集。

- **风格**：实验工作室/研风（research lab aesthetic）。极简 UI 包裹高复杂度视觉焦点：首页只有一块全屏着色器画布（噪声场、粒子流或网格变形）+ 悬浮其上的站点名与身份。
- **排版**：UI 层保持极简单一无衬线（画布已足够复杂，文字必须冷静）；字号小、层级少，一切让位于画面。
- **色彩**：画布色板由主题 token 控制（2-3 色调色板，如靛蓝-品红-米白或石墨-青柠）；列表页回归静态配色，画布只出现在首页与项目页头图，避免全站疲劳。
- **动效**：这是核心——GPU 粒子/着色器跟随鼠标与滚动形变；新闻卡片以「数据流入画布」的方式渐入；页面转场用 View Transitions API 做画布连续性。AI 结合最炫：一个 prompt 输入行，访客用自然语言描述「想要什么感觉」，AI 调整画布参数（配色、流速、颗粒度）并持久化到 localStorage——「AI 个性化体验」直接可视化。
- **如何体现站长技术**：WebGL/WebGPU + shader + View Transitions + AI 参数控制，是前端能力天花板级组合；生成的每一个画面都是不可复制的个人签名。
- **推荐理由**：「最前沿技术 + AI 结合 + 有特色」三条要求拉满；记忆点最强，容易被转发；AI 个性化画布是同类个人站中几乎没人做过的点。
- **风险**：实现成本与后续维护成本最高（着色器调试、跨设备表现差异、移动端功耗/发热）；无障碍红线（光敏性、reduced-motion 必须提供静态帧降级）；与「极简首页」存在张力——画面复杂 vs 版面极简需要非常克制的设计才能兼得；构建产物偏大，GitHub Pages 首屏性能需要专门优化（懒加载、预计算静态帧）。

## 推荐结论

**首选方向 B（瑞士排版 + 动态字体），以方向 A 的工程细节作为佐料，C 留作后续升级路线。**

理由：
1. B 最稳、最快落地、A11y/性能最佳，且差异化最强——developer 圈子里暗色终端已泛滥，编辑部式个人站反而是陌生面孔。
2. B 的「前沿」是原生 CSS（scroll-driven animations、view transitions、variable fonts、container queries），不引重型库即符合 GitHub Pages 轻量部署，也与前端同学的选型汇报可无缝对齐。
3. 吸收 A 的编号系统、⌘K 命令面板、终端式微交互作为点缀，保留工程身份认同。
4. C 的 AI 生成画布可作为 P2 阶段增强项（首页画布彩蛋），不在首期承担风险。

分阶段建议：首期 = B + A 细节；二期 = 引入 C 的 AI 个性化元素（先以轻量 Canvas 而非重型 shader 试水）。

## 设计侧头脑风暴功能点（供项目汇总，超出 6 条硬性内容）

1. **⌘K 命令面板导航**：全站任意页面呼出，搜索新闻/页面/跳转外链，输入 `:` 显示彩蛋命令（如 `:resume` 打开弱化入口的简历）。开发者习惯友好，实现成本低。
2. **「查看源代码」模式**：页脚隐藏入口一键切换——当前视图旁浮现本页面真实的组件树/样式 token 注释（构建期注入），把「网站解释自己」做成技术名片，与简历弱化入口天然呼应。
3. **AI 生成的新闻摘要与标签**：业内新闻构建期由 LLM 生成一句话简介 + 主题标签（后端/AI 同学已评估可行性），列表页可按标签筛选——内容与 AI 结合，而非仅界面结合。
4. **Scroll-driven 进度书脊**：新闻长列表右侧一条极细的 CSS 原生滚动进度指示，滚动时实时显示当前条目编号，零 JS 的前沿 CSS 展示点。
